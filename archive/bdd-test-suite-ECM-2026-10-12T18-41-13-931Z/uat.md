Target facts for ECM (Electronic Catalog Maker): a static, fully client-side site (no HTTP API, no database). Everything below was observed on the real running app with the same Chromium the tests use; treat it as ground truth and do not contradict it.

## 1. URLs (environment contract)
- `process.env.FRONTEND_URL` = `http://localhost:4300`: an origin only (no path, no trailing slash). It is a SECURE context. Always build `${FRONTEND_URL}/editor/`, `${FRONTEND_URL}/viewer/`, `${FRONTEND_URL}/composer/`. Never read EDITOR_URL / VIEWER_URL / COMPOSER_URL.
- `process.env.INSECURE_FRONTEND_URL` = `http://host.docker.internal:4300`: the same site as a NON-secure context (window.isSecureContext === false). Use it ONLY for scenarios that are about behaviour without HTTPS.
- The Viewer opens a demo catalog directly: `${FRONTEND_URL}/viewer/?src=/demo/<file>.ecatm`.

## 2. Fixtures (never invent names)
- `process.env.ECM_REPO_DIR` is the repo root. Demo catalogs (all .ecatm) in `${ECM_REPO_DIR}/demo/`: auto-spare-parts, cell-biology, cosmetologist-{en,ru,uk}, diy-stool-{en,ru,uk}, fitness-{en,ru,uk}, furniture, living-room, nail-techs-{en,ru,uk}, product-grid, quiz-cell-biology-en, quiz-citizenship-en. The password-protected demo is `diy-stool-en.ecatm`, password `stool-2026`.
- The only image files in the repo are in `${ECM_REPO_DIR}/landing/`: og-default.png, og-schools.png, icon-192.png, favicon-32.png, favicon-16.png.
- Anything else (photos for the Composer, CSV tables, big images) must be created at test runtime inside os.tmpdir(): write a PNG with Node's zlib (a solid-colour image is enough) and a CSV with fs. Composer photos must be named by number: `1.png`, `2.png`, ...
- `furniture.ecatm` has exactly 3 rows: `shk-001` Cornice SHK-001, `shk-002` Door panel SHK-002, `shk-003` Drawer SHK-003 (each with an "Add to cart" button and one hotspot).

## 3. Rules the generated code MUST follow (these were the real defects of earlier drafts)
1. File pickers: Save/Open use the File System Access API, which in headless Chromium silently does nothing. Before the FIRST `page.goto` of every test call `await page.addInitScript("delete window.showSaveFilePicker; delete window.showOpenFilePicker;")` (a STRING, never a function). Do it inside the step that opens the page (or a Before hook), never in a separate step that runs after navigation. After that Save is a normal browser download and Open uses the plain file inputs below.
2. Native dialogs: "New catalog" opens `window.prompt`. Register `page.once('dialog', d => d.accept('<name>'))` BEFORE clicking, and accept/dismiss INSIDE that handler. Never stash the dialog for a later step: an unhandled prompt freezes the click forever. For the "empty name" case accept with an empty string.
3. No vacuous assertions. Forbidden: `.catch(() => {})` on an expect, `a || b || !flag` style assertions, "either an error or nothing happened", `toBeTruthy()` on a count of 0 or more. Each Then asserts ONE concrete observable fact from section 4. If a behaviour is not listed in section 4, keep the scenario but assert only what is listed and mark the rest with a `# TODO (unconfirmed)` comment.
4. Step definitions: Cucumber matches step TEXT only; the Given/When/Then keyword is ignored. So a phrase must be defined EXACTLY ONCE for the whole file even when different scenarios use it with different keywords (e.g. "I create a new catalog named {string}" used as Given in one scenario and When in another is ONE definition, registered with any one keyword). Reuse identical wording across scenarios instead of writing near-duplicates, and before finishing re-read your steps file and delete every repeated pattern. Never define both `{int} item(s)` and `{int} items`. Do not add steps that do nothing.
5. Chromium only, no Collaboration Server.

## 4. Observed behaviour and stable selectors
### Editor (`/editor/`)
- Toolbar ids: #btn-new, #btn-open, #btn-copy-remote, #btn-add-image (enabled only once a catalog exists), #btn-save, #btn-undo, #btn-redo, #btn-export, #btn-export-protected, #btn-export-pdf, #btn-search, #btn-zoom-out. File inputs (use setInputFiles directly, hidden): #file-image, #file-open.
- document.title is "Electronic Catalog — Editor"; it starts with "● " while there are unsaved changes and the mark disappears after Save.
- Add image via #file-image; the image appears as #stage-img (attached) and in `.image-list-name`. Click inside #stage-img's bounding box at an offset to place a hotspot; this shows the link form `#form-link` (`input[name=name]`, `input[name=url]`, `button[type=submit]`) and then the row form `#form-row` (`input[name=name]`, `input[name=sku]`, `button[type=submit]`). Hotspots: `#stage-inner .hotspot:not(.pending)`; saved rows: `tr[data-row-id]`. Undo/Redo: Control+z / Control+Shift+z or #btn-undo / #btn-redo.
- Save downloads `<name>.ecatm`; the file is a SQLite database (first 15 bytes "SQLite format 3").
- Leaving the page with unsaved changes fires a native `beforeunload` dialog (observable with `page.close({ runBeforeUnload: true })` and a dialog handler checking `dialog.type() === 'beforeunload'`).
- Export protected: #btn-export-protected opens a form with #protect-password, #protect-repeat, #protect-submit ("Protect and download"), #protect-cancel. On FRONTEND_URL (secure) filling both fields with the same password (>= 8 chars) and clicking #protect-submit downloads `<catalog name>_protected.ecatm`. On INSECURE_FRONTEND_URL the same action produces NO download.
- Do not guess behaviour for duplicate addresses, huge images or remote URLs: it was not observed. Assert only that the app stays usable (title still "...Editor", #btn-new still visible) and add a TODO.
### Viewer (`/viewer/`)
- Toolbar ids: #btn-open, #btn-open-remote, #btn-refresh, #btn-search, #btn-share-view, #btn-export-pdf, #btn-cart (text "🛒 Cart (N)"), #lang-select, #btn-theme, zoom #btn-zoom-out/#btn-zoom-in/#btn-zoom-reset/#btn-zoom-fit. File input #file-open (hidden).
- Rows: `tr[data-url='<address>']`; hotspots `.hotspot[data-id]`; clicking a hotspot adds class `selected` to its row (and selecting a row selects its hotspot).
- Search: click #btn-search to open the panel: `#search-input` (placeholder "Search every row…"), `#search-field` (select: All fields / Name / SKU / Description / Extra: …). Matches are listed in `.search-results` (e.g. searching "door" lists "Door panel · SHK-002"); the table rows themselves are NOT filtered.
- Cart: every row has `button.buy-btn` ("Add to cart"; after click it becomes "In cart ✓" with class `in-cart` and #btn-cart text becomes "🛒 Cart (1)"). There are several .buy-btn: use `.nth(i)` or `.first()`, never a bare getByRole (strict-mode violation). Clicking #btn-cart shows `.cart-remove-btn`, #cart-clear ("Clear cart"), #cart-checkout ("Checkout (N)").
- Protected catalog (`diy-stool-en.ecatm`): the viewer shows `#lock-password` and `#lock-submit` ("Unlock"; disabled until a password is typed). On FRONTEND_URL (secure): a wrong password shows `.error` "Wrong password, or the file was modified. Check the password and try again." and no rows; the right password (`stool-2026`) hides #lock-password and shows 6 rows and 6 hotspots. On INSECURE_FRONTEND_URL the page shows `.error` containing "Encryption is not available here: the page must be served over HTTPS" and #lock-submit stays disabled, so the catalog can never be opened. Always click #lock-submit; Enter does not submit.
- Quiz demo (`quiz-cell-biology-en.ecatm`) renders and is interactive; assert only what is visible after load.
### Grid Composer (`/composer/`)
- h1 "ECM Grid Composer". Controls: #name (catalog name), #columns (2-6), #fit, #subtitle, #accent, #lang, #theme, #template ("Download template" downloads `grid-composer-template.csv`).
- Photos: hidden file input `#photo-files` (also #photo-folder); status `.status` text "Photos: N". Table: hidden file input `#table-file` with a CSV (first row = headers `No.,Folder,Name,SKU,Description`), or paste into `#paste`; status `.status` text "Rows: N · extra keys: none".
- Report: `.box.ok` "Every row has a photo and every photo has a row." when numbers match; `.box.warn` "Warnings (the build still works) No photo for No. 3, 4 — a “no photo” tile is drawn instead." when a row has no photo (a photo whose number has no row is also a warning). The build still works with warnings.
- Build: click `#build` ("Build catalog"); section "5. Catalog" appears with links `a.btn.primary` "Download .ecatm", `a.btn.secondary` "Open in Editor", `a.btn.secondary` "Open in Viewer". There is NO #add or wizard in this page; ignore those.
### Security-related observations
- The app renders user text as text. To test XSS: put `<img src=x onerror=window.__xss=1>` into a catalog name / hotspot / row field, then assert `window.__xss` is undefined and the text is visible literally. Do not claim anything about javascript: URLs, SSRF or rate limiting beyond what a visible UI result proves: for those scenarios assert only the app remains functional and add a TODO.
